# lib/auth/
> L2 | Parent: /CLAUDE.md

Better Auth wrapper — auth config, organization/seat layer, server session guards, client hooks, permission predicates.

Files
- index.ts: Server-side Better Auth instance (Google/GitHub OAuth, magic link, email OTP, Turnstile captcha, admin, anonymous and organization plugins; Upstash rate limiting; Drizzle adapter). The admin plugin carries the ./admin-access table, and its adminRoles includes superadmin — that is what makes admin accounts un-impersonatable (allowImpersonatingAdmins stays off) — with borrowed sessions expiring after an hour. Hooks: user.create.before blocks blocklisted signup emails and IPs (one Redis read serves both tests; no source IP means no IP block), user.create.after hands the source IP and device-signal cookie to signup-rewards.ts (cluster gate, then the welcome gift) and records attribution, deleteUser.beforeDelete refuses users with a live subscription or an organization they own. The session IP header order is lib/ip's CLIENT_IP_HEADERS, so rate limiting, session.ipAddress and userSource attribution all read the same address.
- signup-rewards.ts: grantSignupRewards, the signup reward orchestration called by index.ts' after hook: lib/signup-gift-gate decides per identity cluster (source IP + device fingerprint), a withheld gift logs a warn and sends Discord notifySignupGiftWithheld, an allowed one calls the ledger's once-only grantSignupBonusCredits. Nothing throws; a broken gate lets the gift through.
- admin-access.ts: Admin-plugin access table (ac + the user/admin/superadmin roles) — **impersonate is granted to superadmin alone** (borrowing a session exposes everything the user sees and spends their credits, so it sits above day-to-day admin work); the plugin ships knowing only admin/user, so leaving superadmin undeclared would fail every authorize() call. Shared verbatim by index.ts and auth-client.ts, and holds the borrowed-session lifetime (1 hour).
- organization.ts: Organization plugin config — invitations expire in 48h, seat cap enforced on invite/accept/add plus a concurrency reclaim under an advisory lock, getOrgSeatCap resolves the cap from the organization's live team subscription, beforeDeleteOrganization refuses organizations with any financial history, sendInvitationEmail sends the emails/organization-invitation template.
- server.ts: Server-only session helpers, two channels: getSession (cookie cache, hot path) and getFreshSession (bypasses the cache; bans, revocations and demotions apply immediately, and it writes no cookie back, so a Server Action guarded by it does not drag a route re-render along) — both deduped per request with React cache(). isAdmin / isSuperAdmin are pure booleans over the fresh channel (no redirect side effect; AuthGuard owns page redirects). getWorkspaceContext revalidates membership on every call and falls back to the personal workspace.
- auth-client.ts: Client authClient (better-auth/react) with the plugin set aligned to the server, admin included — it carries the same ./admin-access table, which is what puts impersonatedBy on the session type for ImpersonationBanner to read.
- permissions.ts: Pure predicates isAdminUserRole / isSuperAdminUserRole, usable on both server and client.
